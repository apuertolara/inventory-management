Factory Inventory Management System

A demo web app with two parts: a Vue 3 frontend that runs in the browser, and a small Python FastAPI backend that serves sample data from JSON files. There is no database. All data is loaded into memory when the server starts and is filtered there for each request.

System architecture

Two processes run on your machine. The browser loads the app from Vite on port 3000, then calls the API on port 8001 directly (CORS allows it).

Tech stack

Kept small on purpose: three runtime libraries on each side.

Frontend

client/

  • Vue 3.4, Options-style setup() functions
  • vue-router 4 for page URLs
  • axios for HTTP calls
  • Vite 5 for the dev server and builds
  • Charts drawn by hand in SVG, layouts in CSS Grid
  • No state library: shared state lives in composables
Backend

server/

  • Python 3.11+
  • FastAPI for routes and /docs
  • Pydantic 2 for response shapes
  • Uvicorn web server
  • uv installs packages and runs the app
  • generate_data.py creates sample JSON
Testing & tooling

tests/, scripts/

  • pytest with FastAPI TestClient
  • 40 backend tests across 3 files
  • No frontend tests
  • scripts/start.sh / stop.sh run both servers
  • Playwright MCP for checking pages in a browser

Data flow: changing a filter

What happens when a user picks "Tokyo" in the Location filter while on the Overview page.

  1. FilterBar updates shared state useFilters.js keeps its refs at module level, so every page sees the same selectedLocation.
  2. The page notices the change Dashboard.vue watches the filter refs and reloads its data.
  3. Filters become query params getCurrentFilters() maps Location to warehouse and Time Period to month. api.js leaves out any value set to all.
  4. Parallel requests Dashboard fires four calls at once: summary, orders, inventory and backlog.
  5. FastAPI filters in memory apply_filters() then filter_by_month() run list comprehensions over the lists loaded at startup.
  6. Pydantic checks the shape Routes with a response_model drop unknown fields and fail loudly on bad data.
  7. Vue derives what is shown Raw results go into refs (allOrders, inventoryItems). KPIs, charts and tables are computed properties, formatted in USD or JPY by locale.

Shared code

  • api.js: every HTTP call in one place
  • composables/useFilters.js: the four global filters
  • composables/useI18n.js: English and Japanese text; the chosen language is saved in localStorage and also sets the currency
  • composables/useAuth.js: a hard-coded demo user and task list (no real login)
  • utils/currency.js: USD formatting, and JPY at a fixed rate of 150
  • locales/en.js, locales/ja.js: translation strings

Known gaps

Places where the code and the running app disagree. Useful to know before changing things.

Frontend calls endpoints that don't exist api.js has functions for /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (GET, POST), but the backend has no such routes. The Tasks modal gets a 404 on page load.
PurchaseOrderModal is used but never imported Dashboard.vue renders <PurchaseOrderModal>, but the component isn't registered and no file for it exists, so "Create PO" can't open a form.
Reports.vue bypasses api.js It calls axios with the full http://localhost:8001 URL written in, so changing the base URL in api.js won't reach it.
Backlog page has no route views/Backlog.vue exists but isn't registered in main.js. Backlog data only appears on the Dashboard.
Test docs are out of date tests/README.md lists test_orders.py, which isn't in the repo.
